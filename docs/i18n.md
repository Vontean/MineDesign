# 界面文案与语言维护

产品界面只支持 `en` 与 `zh-Hans`。词典源码是唯一事实来源；CSV 是审核、导出与迁移记录，不在运行时加载，也不要求与代码手工同步维护。运行 `npm run export:i18n` 可将当前领域词典和外壳词典（含动态分支）导出到 `output/i18n/minedesign-bilingual.csv`；修改以词典源码为准。

## 从哪里改

- `packages/contracts/src/ui-text/*.en.ts` 与同名 `*.zh-Hans.ts`：按 shell、canvas、inspector、design-system、feedback、errors 管理。
- `ui-messages.ts`：带类型的语义 key、参数格式化。新词条使用这个入口。
- `ui-text.ts`：外壳既有的 `uiText(locale)` 接口；`*.legacy.*.ts` 保持旧调用兼容。不要再往单个大对象持续追加不同领域的文案。
- `ui-locale.ts`：页面内的语言状态与订阅；不依赖评论、作品或 React。
- `packages/editor-host/src/shared/ui-locale.ts`：初始化编辑器语言，并接收经过宿主桥校验的 `editor:locale` 消息。
- 两套 runtime 的 `ui-locale.ts`：React 订阅。语言变化更新原组件，不重建作品或编辑状态。
- `ui-error.ts`：稳定错误码到用户提示；`service-errors.mjs` 是 HTTP/MCP 共用的错误载荷契约。
- `ui-format.ts`：受语言影响的字重名与相对时间。
- `ui-value.ts`：只在显示处格式化 CSS 枚举、操作词与节点种类；模型标签、枚举值和作者自定义名称保持原样。

## 新增或修改

1. 先找到控件和实际触发条件。确认它属于产品外壳，还是用户作品、代码、图标或素材名称。
2. 在所属领域增加稳定的语义 key，并同时填写中英文。key 描述用途，例如 `canvas.pages.deleteConfirm`，不使用行号、CSV 编号或完整英文句子。已有 key 不随措辞调整而改名。
3. React 组件调用 `useUiLocale()` 订阅语言，用 `uiMessage('领域.key')` 渲染；外壳按当前 locale 取词典。不要在模块启动时缓存翻译后的 label；静态选项可用 label getter，组件中的选项在渲染时生成。
4. 动态文案使用完整句子和命名参数。不要新增 `"Delete " + name` 片段，不翻译参数中的用户内容；富文本保留原组件结构。参数必须在两种语言中一致，数量与语序可由语言决定。
5. 检查当前模块的标题、菜单、tooltip、placeholder、禁用原因、ARIA、空状态、操作结果、错误与重试。控件 `value`、图标名、CSS 属性、文件路径、消息名称和测试标识保持稳定。

语言优先级：用户明确选择 → Codex 宿主 locale → 浏览器语言 → 英文。中文语言标签映射为简体中文；其他未支持语言回退英文。独立打开编辑器也使用同一解析规则。不要改写画板文字、规范内容、用户名称或用户素材；切换界面语言不得触发作品保存、页面刷新或丢失编辑。

## 文案约定

中文面向设计师，说明动作、结果和恢复方法，避免不必要的“您”“请”“进行”。英文使用 sentence case，保留专名、代码与格式名的大小写。常用术语：设计稿 design、画板 artboard、画框 frame、画布 canvas、设计系统 design system、属性 properties、填充 fill、描边 stroke、圆角 radius、间距 spacing、外边距 margin、内边距 padding、文字样式 text style、素材 asset、评论 comment、批注 annotation、设计变量 token。

按语境复用：Filter 在列表中是“筛选”，在图像效果中是“滤镜”；Group 的编组操作和组名称可使用不同 key。Agent、MineDesign、Codex 等名称沿用产品现有称谓。无需本地化的单位、HTML/CSS 代码、格式名与字体预览样本不应强行翻译。

错误通过 `code` 传递，在显示处按当前语言解析。保留原始 message 用于详情或诊断。未知错误使用通用提示，不把路径、英文异常或猜测的原因直接放进普通状态消息。保存冲突、过期评论和失败重试要保留原有恢复动作。

## 完成标准

- `npm run check:i18n`：实际执行 TypeScript 检查，并验证中英参数、调用 key 与明确界面位置的硬编码。少量非文案例外在 `scripts/i18n-allowlist.json` 说明原因，不能用宽泛文件夹忽略真实控件。
- `npm run test:modules`：词典、动态参数、语言优先级、错误映射和宿主语言桥回归；HTTP/MCP 变更另执行构建后的 `npm test`。
- 真实打开受影响界面，切换中英，核对菜单、提示、错误、长文和窄面板。至少确认当前选择、输入草稿与未保存编辑没有因语言切换丢失。
- 修改事实、接口或流程时同步本文件及架构路由；先保证产品行为，再报告测试、浏览器预览与 Codex 宿主验收的不同边界。
